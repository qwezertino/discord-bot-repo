# Discord Bot Panel

Отдельный проект, скопированный из `perimeter_fivem/tools/discord_bot`.
Исходная панель и её данные сохранены на месте. В этом проекте нет токенов,
старой SQLite и загруженных файлов.

Поддерживаются несколько ботов в одном приложении: у каждого свой профиль,
Discord-клиент, история публикаций, вложения, reaction roles и журнал.
Игровые интеграции пока не реализованы.


Автономный Discord-бот и веб-панель для публикаций, редактирования собственных
сообщений, embed, файлов и ролей за реакции. Docker, WSL и внешние сервисы не
нужны. Настройки хранятся в SQLite внутри `data/`.

Редактор сообщения и описания embed содержит кнопки Discord Markdown: жирный,
курсив, подчёркивание, зачёркивание, спойлер, код, цитата, список и ссылка.
После выбора сервера панель также позволяет вставлять каналы и роли из списков
без ручного копирования ID. Кнопка `@everyone` и выбор роли автоматически
включают разрешение реальных упоминаний для отправляемого сообщения.

В основном тексте, описании embed и значениях его полей работает автодополнение
Discord-тегов. `@` открывает роли плюс `@everyone`/`@here`, а `#` - каналы
выбранного сервера. Варианты выбираются мышью, стрелками и Enter/Tab. Если
набранное имя совпадает полностью, пробел также подтверждает подстановку.
Упоминания из embed отображаются как теги, но не отправляют уведомлений:
реальный пинг должен находиться в основном тексте сообщения.

В обычном тексте доступны два режима ссылок: **URL + превью** вставляет голый
URL, по которому Discord может построить карточку сайта, а **Текст-ссылка**
создаёт masked Markdown `[текст](URL)`. Для автоматической карточки у роли бота
должно быть разрешение **Embed Links**, а сам сайт должен отдавать Discord
доступные Open Graph metadata.

В описании и полях embed работают обычные URL и masked-ссылки. Они отображаются
кликабельными, но Discord не строит вложенную карточку сайта внутри другого
embed. Для карточки URL нужно оставить в основном тексте сообщения; для
кликабельного заголовка используется поле **Ссылка заголовка**.

В форме reaction roles есть локальный поисковый каталог из более чем 3000
полностью квалифицированных Unicode-эмодзи. Каталог поставляется Python-пакетом
`emoji` и после установки зависимостей не обращается к внешним сайтам. Ручной
ввод сохранён для кастомных эмодзи конкретного Discord-сервера.

## Что нужно от Discord

Если бот уже добавлен на сервер, приложению нужен только его **bot token**.
Application ID необязателен; если указан, панель сверяет его с подключённым
приложением. Client secret для локальной панели не требуется.

В [Discord Developer Portal](https://discord.com/developers/applications):

1. Открыть приложение и раздел **Bot**.
2. Включить **Server Members Intent** в блоке Privileged Gateway Intents.
3. Скопировать или сбросить token и записать его только в локальный `.env`.

**Message Content Intent** текущим функциям панели не требуется, но его можно
включить в Developer Portal для будущих текстовых команд и обработки сообщений.

Роль бота на сервере должна иметь:

- View Channels;
- Send Messages;
- Embed Links;
- Attach Files;
- Add Reactions;
- Read Message History;
- Manage Roles.

Роль бота должна находиться выше всех ролей, которые он выдаёт. По умолчанию
панель запрещает reaction-role правила для ролей с Administrator, Manage Server
или Manage Roles.

## Docker, Nginx и размещение в /panel

Подготовлен Docker Compose для приложения, Nginx и Certbot. Адрес по умолчанию:
`https://IP:8443/panel/`. У контейнера приложения нет опубликованного порта;
SQLite и вложения находятся в постоянном bind mount, секреты монтируются
отдельным `.env` только для чтения и не попадают в образ.

Инструкции установки, TLS на IP, переноса данных, обновления и продления
сертификатов: [docker/README.md](docker/README.md).

`PANEL_BASE_PATH=/panel` включает префикс для интерфейса, API, файлов и OAuth.
Callback должен включать тот же префикс и внешний порт, например
`https://89.117.62.251:8443/panel/auth/discord/callback`. Пустое значение сохраняет
обычное размещение в корне сайта.

## Вход через Discord и права пользователей

Режим задаётся явно: `PANEL_AUTH_MODE=local` сохраняет прежний локальный доступ
(или общий Basic Auth), `PANEL_AUTH_MODE=discord` включает персональный вход.
В локальном режиме каждый допущенный к панели посетитель является администратором;
для раздельного доступа команды включите Discord. Активный локальный режим виден
в уведомлении над списком ботов.

Для настройки Discord OAuth:

1. В [Discord Developer Portal](https://discord.com/developers/applications)
   выберите приложение для входа. Можно использовать приложение существующего бота:
   один OAuth-вход обслуживает всю панель, новый бот для него не нужен.
2. В разделе OAuth2 добавьте Redirect URL. Для локального запуска:
   `http://127.0.0.1:8765/auth/discord/callback`.
3. Скопируйте Client ID и Client Secret в локальный `.env`. **Client Secret — это
   секрет OAuth-приложения, отдельный от Bot Token.** Не отправляйте его в чат.
4. Укажите Discord User ID владельца. Владелец определяется только настройкой;
   первый посетитель не получает административные права.
5. После заполнения параметров переключите режим на `discord` и перезапустите
   только эту панель:

   ```dotenv
   PANEL_AUTH_MODE=discord
   PANEL_OWNER_DISCORD_ID=ваш_Discord_User_ID
   DISCORD_OAUTH_CLIENT_ID=Application_ID_приложения_для_входа
   DISCORD_OAUTH_CLIENT_SECRET=секрет_из_раздела_OAuth2
   DISCORD_OAUTH_REDIRECT_URI=http://127.0.0.1:8765/auth/discord/callback
   PANEL_SESSION_HOURS=12
   ```

6. Откройте `http://127.0.0.1:8765`, войдите через Discord. Адрес должен совпадать
   с настроенным Redirect URL: `localhost` и `127.0.0.1` не взаимозаменяемы для OAuth.

В режиме Discord неполная настройка останавливает запуск с понятной ошибкой;
возврата к незащищённому доступу автоматически не происходит. Общий Basic-пароль
в этом режиме не используется и не позволяет обойти персональный вход.

Владелец видит вкладку **Користувачі та доступ / Users and access**. Можно заранее
вписать Discord ID человека, выбрать бота и назначить уровень доступа:

| Уровень | Возможности |
| --- | --- |
| Владелец | Все боты, их настройки/подключение, пользователи и выдача доступа |
| Керівник / Operator | Публикации, вложения, импорт и reaction roles назначенного бота |
| Спостерігач / Viewer | Просмотр серверов, каналов, ролей, сохранённых сообщений, правил и журнала |
| Без доступу / No access | Бот скрыт, API этого бота недоступен |

Новые пользователи после входа не имеют назначенных ботов. Права проверяются на
сервере при каждом запросе, включая прямые обращения к API. Назначение бота даёт
доступ ко всем серверам, на которых присутствует этот бот; ограничение отдельных
каналов/серверов пока не реализовано. Управляющие не меняют токены, профили,
подключения или права других пользователей. Изменение прав применяется к новым
запросам сразу; уже начатая операция может закончиться.

**Блокировка пользователя** завершает все его сессии и запрещает новый вход.
Разблокировка позволяет войти заново, но старые cookies не восстанавливаются.
Снятие доступа к одному боту сохраняет остальные назначения. Владелец не может
заблокировать себя или снять собственные права через панель. Для смены владельца
нужно изменить `PANEL_OWNER_DISCORD_ID` на сервере и перезапустить панель.

В журнале действий сохраняется Discord ID исполнителя. Для локального
администратора используется `local`, для фоновых событий бота — пустой actor.
Схема v2 добавляет пользователей, назначения и сессии, сохраняя существующие
публикации, вложения, профили и историю.

Авторизация использует [Discord OAuth2 Authorization Code](https://docs.discord.com/developers/topics/oauth2)
с областью `identify`, одноразовым `state`, привязкой к браузеру и PKCE S256.
OAuth access/refresh tokens не сохраняются. В SQLite находятся только хеши
случайных сессионных токенов; cookies имеют HttpOnly/SameSite=Lax, а при HTTPS —
Secure и префикс `__Host-`. Запросы изменения данных требуют CSRF-токен.
Сессии истекают через указанное число часов (1–168). **Выйти / Sign out** завершает
текущую сессию.

Для удалённой команды задайте постоянный HTTPS-адрес панели за reverse proxy и
соответствующий Redirect URL. Панель сама не открывает порт, не создаёт туннель и
не использует игровой OAuth callback. Прокси должен сохранять Host (включая порт,
если он указан) и передавать корректный X-Forwarded-Proto; доверяйте forwarded
заголовкам только от самого прокси. HTTP для OAuth допустим только на localhost.
В access-логах Uvicorn параметры callback скрываются; на reverse proxy тоже
исключите query-параметры этого URL из логов.

## Язык интерфейса

Панель доступна на украинском и английском. Переключатель **Мова / Language**
находится в шапке. По умолчанию выбран украинский; выбор сохраняется в браузере.
Язык меняется без перезагрузки: выбранный бот, черновик, embed и вложения
сохраняются. Тексты сообщений, имена ботов, серверов, каналов, ролей и файлов
не переводятся. Даты, уведомления и названия действий журнала используют
выбранный язык.

API принимает `Accept-Language: uk` или `en` для ошибок и состояния подключения.
Сохранённые данные и коды действий журнала от языка не зависят. Общий словарь
находится в `app/static/translations.json`.

## Профили и два бота

Панель запускается без токенов. Профиль `default` создаётся автоматически и
показывает подсказку о настройке. В верхней части интерфейса доступны выбор
бота, **Добавить бота**, **Настройки** и **Переподключить**.

Для Iron Crown и Perimeter:

1. Запишите токены только в локальный `.env`:

   ```dotenv
   IRON_CROWN_BOT_TOKEN=ваш_токен_первого_бота
   PERIMETER_BOT_TOKEN=ваш_токен_второго_бота
   ```

2. Запустите панель. Если эти переменные заполнены, профили **Iron Crown** и
   **Perimeter** появятся автоматически. Пустой служебный профиль «Основной бот»
   будет убран, если он не настроен, не содержит данных и старый токен отсутствует.
3. При желании укажите Application ID в настройках профиля. Существующие профили
   с этими env-ссылками повторно не создаются и не переименовываются. Других ботов
   можно добавить кнопкой **Добавить бота**. Внутренний ID после создания не меняется.
4. Для каждого приложения включите intents и права из раздела выше.
5. Если `.env` изменён после запуска процесса, перезапустите **только панель**.
   Кнопка переподключения использует уже загруженное окружение процесса.

Токены не сохраняются в SQLite и не возвращаются API. Профиль хранит имя
переменной окружения. Не вставляйте токен в поле имени переменной.
Отключение профиля закрывает его клиент, сохраняя данные. Изменение настроек
перезапускает только выбранный клиент. Автоматическое восстановление сетевого
соединения выполняет discord.py; после ошибки токена/intents исправьте настройку
и переподключите бота. Переключение бота в браузере клиентов не создаёт.

При смене бота черновик сбрасывается, включая файлы, embed и упоминания;
история и серверы загружаются заново. Незавершённая отправка или импорт могут
закончиться для прежнего бота, но их ответ не изменит новый профиль.
Проверяйте имя в селекторе и предпросмотре перед отправкой.

Настройка выдачи административных ролей задаётся отдельно в каждом профиле.
`ALLOW_PRIVILEGED_REACTION_ROLES` применяется к `default` только при первом
создании профиля, далее действует сохранённая настройка.

## Переход со старой панели

Остановите панель и сделайте резервную копию её `data/`, включая SQLite и
вложения. При запуске миграции схемы v1/v2 в транзакции закрепят все старые записи
за `default`, сохранив ID, даты, payload, имена файлов и счётчики записей.
Повторный запуск миграции безопасен. Профиль `default` по умолчанию использует
прежний `DISCORD_BOT_TOKEN`: менять `.env` для одного бота не требуется.
Существующие данные соседних проектов автоматически не копируются.

Все операции инструментов используют `/api/bots/{bot_id}/…`;
общие маршруты — `/api/bots` и `/api/emojis`. Старые маршруты без bot_id
удалены, чтобы выбор владельца был явным. Публикации и reaction roles уникальны
внутри профиля, доступ по внутреннему ID чужой записи возвращает 404.
Discord ID в API передаются строками.

Менеджер `app/bot_manager.py` управляет клиентами, а `Database.scoped(bot_id)`
ограничивает SQL владельцем. Будущий игровой адаптер должен явно получать
профиль и его сервис; общие инструменты не читают игровые файлы и базы.
Источником истины игровых привязок останется БД игры. Запускайте один процесс
панели (один Uvicorn worker), чтобы не создавать дубли Gateway-клиентов.

## Первый запуск на Linux/VPS

Требуется Python 3.12 или новее и пакет `python3-venv`.

```bash
cd /path/to/discord-bot-panel
cp .env.example .env
nano .env
chmod +x run.sh
./run.sh
```

При первом запуске `run.sh` создаст `.venv` и установит зависимости. Следующие
запуски используют готовое окружение.

Если система сообщает `No module named pip`, установить поддержку виртуальных
окружений и повторить запуск:

```bash
sudo apt update
sudo apt install python3-venv
./run.sh
```

Скрипт обнаружит неполную `.venv` и автоматически пересоздаст её.

Панель по умолчанию доступна только на VPS по адресу `127.0.0.1:8765`. Открыть
её со своего компьютера безопасно через SSH-туннель:

```bash
ssh -L 8765:127.0.0.1:8765 USER@VPS_IP
```

Пока SSH-сессия открыта, в браузере доступен адрес:

```text
http://127.0.0.1:8765
```

Не выставляй панель напрямую в интернет без HTTPS/reverse proxy. Если указать
`PANEL_HOST=0.0.0.0`, приложение потребует непустой `PANEL_PASSWORD` и включит
HTTP Basic Auth, но TLS всё равно должен завершаться на reverse proxy.

## Запуск на Windows

1. Установить Python 3.12+ с опцией `Add Python to PATH`.
2. Скопировать `.env.example` в `.env` и указать token.
3. Запустить `run.bat`.
4. Открыть `http://127.0.0.1:8765`.

## Постоянный запуск через systemd

После первого ручного запуска скопировать пример unit-файла и заменить
`CHANGE_ME`/пути:

```bash
sudo cp discord-bot-panel.service.example /etc/systemd/system/discord-bot-panel.service
sudo nano /etc/systemd/system/discord-bot-panel.service
sudo systemctl daemon-reload
sudo systemctl enable --now discord-bot-panel
sudo systemctl status discord-bot-panel
```

Логи:

```bash
journalctl -u discord-bot-panel -f
```

## Важное поведение

- Бот редактирует только сообщения, которые были отправлены от его имени.
- История панели хранит Discord message/channel/guild ID и исходную форму embed.
- На вкладке **Отправленные** можно импортировать историю одного канала или всех
  доступных текстовых каналов. Импортируются только сообщения, автором которых
  является текущий bot user; повторный импорт обновляет существующие записи без
  дублей. Можно ограничить глубину на канал или явно выбрать полное сканирование.
- При импорте сохраняются текст, первый пользовательский `rich` embed и
  существующие Discord-вложения. Автоматические link-preview Discord не
  копируются как ручные embed и повторно строятся из URL в тексте.
- Упоминания по умолчанию обезврежены. Для реального `@everyone`, роли или
  пользователя нужно явно включить переключатель перед отправкой.
- Настройки reaction roles переживают перезапуск приложения.
- Реакции, поставленные пока бот был полностью выключен, не доставляются ему как
  события задним числом. Уже выданные роли при этом сохраняются.
- Удаление правила в панели останавливает дальнейшую обработку, но не снимает уже
  выданные роли и не удаляет реакции пользователей.

## Разработка и проверки

```bash
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m pytest
node --check app/static/app.js
node --check app/static/i18n.js
node --check app/static/login.js
node --check app/static/urls.js
node tests/test_frontend.cjs
sh -n run.sh
git diff --check
```

Токен, SQLite и загруженные файлы исключены из Git локальным `.gitignore`.

Тесты используют временные SQLite, mock-клиенты и прямые ASGI-запросы без
внешних сервисов. Node проверяет поздние ответы и изоляцию черновиков.
Подключение к Gateway, реальные права/intents, публикации, импорт истории и
выдачу/снятие ролей нужно дополнительно проверить с настроенным ботом и явным
разрешением владельца на действия в Discord.
